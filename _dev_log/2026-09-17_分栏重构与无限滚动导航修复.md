- **日期**：2026-09-17
- **版本**：v0.3.0

- **环境**：Tampermonkey 油猴脚本（浏览器直连模式）

## 1. 用户多次诉求（User Claims）与演进脉络

在本次迭代中，用户结合宽屏（2048px）实际使用体验与多张视口截图，提出了多轮关键 Claim：

### Claim 1：视觉密度不紧凑，Timeline 与 Detail 比例失衡
* **用户原声**：“不够紧凑啊.你分析下这个图片中有哪些问题.”
* **现象**：在超宽屏下，给左侧分配了过多的宽度（或者粗暴拉伸），导致导航与推文之间、推文与右侧分栏之间留存大面积无效留白，推文内容本身仅约 600px，缺乏统一网格收敛。

### Claim 2：开发链路低效，需要即时热加载
* **用户原声**：“热加载失效了.我没有看到任何效果.甚至我觉得应该进入 hot 加载的开发模式，而不是我手动放到油猴.”
* **现象**：每次修改代码都需要在油猴编辑面板中全选粘贴，不仅繁琐，而且容易受到浏览器缓存影响，无法实现所见即所得的极速迭代。

### Claim 3：左侧导航栏严重变形、文字重叠、账号卡片截断
* **用户原声**：“左侧太靠左了，都出现了重叠... 左侧导航条还是很差劲.”
* **现象**：左侧原生导航栏在通过 CSS 强行限制宽度时，由于全局宽屏下推特渲染的是全宽 Header 组件（包含导航文字标签、带“Post”文本的长胶囊按钮、以及带姓名与 handle 的账号切换器），导致：
  1. 文本在 68px 窄条中挤压换行，与图标重叠；
  2. 底部账号卡片被 `overflow: hidden` 截掉半截，露出错位的两截文字；
  3. 整体视觉粗糙破损。

### Claim 4：Timeline 滚动卡死，下方“不加载了”（卡在 `...`）
* **用户原声**：“timeline不加载了 [截图标注红框：不加载了，底部卡在 ...]”
* **现象**：在推特主时间线向下滚动时，首屏第一条或第二条推文之后，底部无限滚动完全中断，停留于加载 Spinner，无法拉取后续任何推文。

### Claim 5：右侧 Detail 留白过宽，拖拽宽度上限受限
* **用户原声**：“右侧的post宽度还可以继续手动拖动更多,现在留给右侧post的太宽了.”
* **现象**：原配置中 `maxTimelineWidthPx` 仅限制在 760px~960px。在 2048px 宽屏下，即便把 Timeline 拖到最大，右侧 Detail 仍旧占据了超过 1000px 的巨大空白，无法进一步向右压缩。

### Claim 6：主帖重复展示性价比极低，默认应只展示评论，长文串按需拉出
* **用户原声**：“post如果不是长推文,现在的再次显示post性价比极低,会重复显示... 如果你认为留下post,那么我觉得默认post应该隐藏到视口,只显示comment. 这样避免这个一样内容的post出现两次,当然用户可以选择在post视口手动把他拉出来,这对长文有好处.”
* **现象**：左侧 Timeline 既然已经在阅读该推文，右侧右侧再从头渲染作者、正文、媒体九宫格，属于严重的信息冗余，浪费屏幕空间；但长文或多推文串（Thread）又有对照阅读的需求。

## 2. 根因深度剖析与工程解决方案

针对上述 Claim，本轮迭代进行了全面的底层根因分析与工程重构：

### 方案 1：建立本地文件直连与开发加载体系（解决 Claim 2）
* **双模支持**：
  1. 新增 `scripts/dev-server.js` 本地轻量级 HTTP 服务（Node.js 原生零依赖，支持 CORS 与无缓存分发）；
  2. 新增 `dev-loader.user.js` 开发版油猴加载器；
  3. 最终通过 Tampermonkey 官方的 `@require file://` 本地文件直连协议，实现 VS Code 保存后按 `F5` 即刻生效的零延迟开发链路。

### 方案 2：彻底治愈推特无限滚动中断 Bug（解决 Claim 4）
* **根因剖析**：
  推特主时间线的虚拟瀑布流由挂载在页面底部的哨兵元素（Sentinel / Spinner）通过原生 `IntersectionObserver` 监测视口相交来触发。
  此前在样式中对 `html` 和 `body` 施加了：
  ```css
  html.xsr-enabled, html.xsr-enabled body { overflow-x: hidden !important; }
  html.xsr-enabled body { padding-right: calc(...) !important; }
  ```
  在 Chromium 渲染引擎中，若对 `html` 声明 `overflow-x: hidden`，会把顶层 Viewport 滚动根容器切断，其子元素的包含块被判定在独立的隐式裁剪容器内。推特的 `IntersectionObserver` 在默认 root（顶级视口）下计算底部元素的 `intersectionRatio` 永远为 `0`，导致无法感知滚动触底，无限加载因此瘫痪。
* **修复落地**：
  1. 彻底删除 `html, body` 上的 `overflow-x: hidden !important`；
  2. 彻底删除 `body` 上巨大的 `padding-right`；
  3. 依靠推特主容器自身的绝对尺寸（`main[role="main"] { width: var(--xsr-timeline-width) }`）与右侧 `#xsr-pane` 的 `position: fixed` 特性进行分栏布局，完美保留原生滚动上下文，推特无限滚动恢复丝滑。

### 方案 3：左侧导航栏脱胎换骨，还原原生 68px 紧凑态（解决 Claim 3）
* **根因剖析**：
  在宽屏模式下，推特前端 JS 判定当前窗口为 Desktop 宽屏，因此渲染了全量的文字与组件。CSS 强行设死宽度却未针对内部元素做紧凑态降级，导致文本溢出和截断。
* **修复落地**：
  1. **容器重塑**：`header[role="banner"]` 固定在 `left: 0; width: 68px;`，开启纵向自适应滚动 `overflow-y: auto`（隐藏滚动条），移除粗暴的 `overflow: hidden`；
  2. **导航图标**：`nav a` 设置为 44px 圆形胶囊，通过 `a span, a div[dir="ltr"] { display: none !important; }` 隐藏文字标签，只留居中图标；
  3. **发推按钮**：`[data-testid="SideNav_NewTweet_Button"]` 限制为 44px 紧凑圆形，内部文字与图标居中对齐；
  4. **底部账号卡片**：在 `[data-testid="SideNav_AccountSwitcher_Button"]` 中隐藏除头像以外的所有文字容器（姓名、@handle、省略号），保留标准的 38px 居中圆形头像，点击仍能正常触发账号弹窗。

### 方案 4：动态放宽 Timeline 拖动上限至 1400px（解决 Claim 5）
* **重构逻辑**：
  ```javascript
  const maxAvailable = Math.max(CONFIG.minTimelineWidthPx + 100, (window.innerWidth || 1920) - CONFIG.navWidthPx - 340);
  const maxLimit = Math.min(CONFIG.maxTimelineWidthPx, maxAvailable);
  const width = clamp(event.clientX - CONFIG.navWidthPx, CONFIG.minTimelineWidthPx, maxLimit);
  ```
* **效果**：在 2048px 宽屏下，用户可以自由把 Timeline 拖到 480px~1400px，右侧 Detail 最小可压缩至 340px，彻底摆脱“右侧留白太大”的困扰。

### 方案 5：默认全屏 Comments 流 + 按需拉出长文串（解决 Claim 6）
* **零冗余默认模式**：
  - `showPost` 默认置为 `false`，状态通过 `localStorage`（`xsr.showPost`）持久化；
  - 进入帖子时，右侧完全不渲染重复的主帖正文与媒体，**100% 满屏展示用户回复流（Comments）**；
  - 顶部增加高密度 **`Mini Anchor`（微型锚点）**：高度仅约 30px，显示作者头像、姓名与一句简要 handle，带 `[Show post]` 按钮。
* **Thread 智能识别与动态展开**：
  - 工具栏提供 `[Show post]` / `[Hide post]` 切换；
  - 当 API 返回该帖属于连推长文（Thread）时，按钮自动感知并显示为：**`[Show thread (N)]`**，并带蓝色强调徽章；
  - 用户点击后拉出主帖与 Thread 串，在大屏上以左右双列对照展示；日常浏览时一键收起，保持极简纯净。

## 4. 吸收 xTweaks UI Enhance 精髓：原生紧凑态视口模拟 (Viewport Spoofing)

在 v0.3.0 初版提交后，针对左侧导航栏仍残留 `More` 文字、发推大黑圈和账号卡片夹扁的问题，进一步吸收了社区优秀脚本 `xTweaks UI Enhance`（GreasyFork 592294）的底层机制：

### 核心认知转变：从“CSS 暴力隐藏”到“驱动推特 React 渲染官方紧凑组件”
* **深层根因**：
  推特前端是纯数据驱动的 React 单页应用。当浏览器在 2048px 宽屏运行时，推特的 React 状态直接初始化为 `isExpandedNavBar = true`，挂载了宽版 DOM（内嵌 `More` 按钮文本、`Post` 文字药丸按钮、带姓名的宽版账号卡片）。任何单纯的 CSS 隐藏不仅容易漏掉像 `div[role="button"]`（More 按钮）这类非链接元素，而且发推按钮无法获得推特官方漂亮的羽毛笔 SVG 图标。
* **xTweaks 吸收方案**：
  1. **视口断点欺骗（Breakpoint Spoofing）**：在 `document-start` 拦截 `window.innerWidth`、`document.documentElement.clientWidth` 与 `visualViewport.width`，在宽屏时将其报告为 `1180px`（处于推特桌面紧凑黄金区间 `1000px ~ 1279px`），促使推特 React 原生挂载官方 Compact Header；
  2. **分栏真实尺寸保全**：在我们自己的脚本中通过闭包持久化原生底层 getter，确保用户拖动分栏时依旧基于 `2048px` 真实屏幕宽度自由拖拽；
  3. **CSS 深度双重兜底**：精准覆盖 `AppTabBar_More_Menu` 与 `[role="button"]` 隐藏残留文字，账号卡片透明无缝化，彻底消灭导航栏一切错位与异物感。

## 5. 新增单向下探悬停预读模式（Downward Hover Lookahead）

### 用户诉求 (User Claim)
* **用户原声**：“这个现在能不能加一个模式. 现在是到达一定的 timeline 的位置之后,右侧的post才会显示. 但是我想我要是鼠标主动放到下一个时间线,他应该也能让post切换. 换句话说,鼠标移动优先. 但是这个移动是当前timeline以下的. 移动到原本触发timeline以上无效. 你能理解我说的吗.”
* **痛点场景**：
  在宽大屏幕下，顶部推文正在阅读线被激活，而用户的视线已经向下看到下一条推文并移动了鼠标。此前必须转动滚轮让下一条推文滚过 35% 阅读线才能切出评论，操作多余；同时，若鼠标向上回移（例如去点顶栏 Tab 或左侧导航），绝不能回退误触旧推文。

### 架构方案与边界纪律
1. **基准锚定**：以滚动判定（Reading Line）为 `scrollTriggeredArticle` 基准；
2. **单向向下判定**：利用标准 DOM API `baselineArticle.compareDocumentPosition(article) & Node.DOCUMENT_POSITION_FOLLOWING` 与视口 `rect.top` 几何双校验，严密判定目标推文是否在基准推文之后；
3. **向上严格无效**：若鼠标移到基准推文上方（`DOCUMENT_POSITION_PRECEDING`），立即中止，绝不发生倒退误触；
4. **悬停微防抖（110ms）**：鼠标轻微掠过不触发网络请求，仅当视线与光标停留于下方目标推文满 110ms 时优先激活切换；
5. **双态协同**：用户转动滚轮时无缝清除悬停定时器，回归原生滚动流驱动；支持油猴菜单快捷开关与 `localStorage` 记忆。
